# Proposer 内部头脑风暴方法

本文档描述 Proposer Agent 如何在内部进行头脑风暴以生成创新解决方案。

---

## 头脑风暴流程

Proposer 在提出解决方案前，在内部进行四阶段头脑风暴：

### 第一阶段：发散探索（生成想法）

**目标**：生成大量多样化想法，数量 > 质量。

#### 核心技术

| 技术 | 描述 | 应用示例 |
|------|------|----------|
| **跨领域类比** | 从其他领域寻找相似之处 | "计算机视觉中的注意力机制如何应用于无线信道估计？" |
| **假设反转** | 翻转核心假设 | "如果信道不是瑞利衰落而是确定性的会怎样？" |
| **尺度转换** | 改变问题尺度 | "从单用户扩展到大规模MIMO会怎样？" |
| **约束操作** | 移除或添加约束 | "如果没有功率约束会怎样？" |
| **技术推测** | 应用新兴技术 | "使用可重构智能表面(RIS)能解决什么问题？" |

#### 内部提示

对于每个技术，Proposer 问自己：
- 这个技术如何应用于当前问题？
- 会产生什么新的可能性？
- 最激进的变体是什么？

**输出**：生成 5-10 个不同的想法种子。

---

### 第二阶段：建立联系（发现模式）

**目标**：识别想法之间的模式、主题和意外联系。

#### 方法

1. **寻找共同线索**
   - 哪些想法共享相同的核心原理？
   - 是否有重复出现的主题？

2. **识别互补想法**
   - 哪些想法可以相互增强？
   - 是否有可以组合的方法？

3. **发现意外联系**
   - 是否有跨领域的联系？
   - 是否有非直观的关联？

4. **映射关系**
   - 想法之间的依赖关系
   - 潜在的组合方式

**输出**：2-3 个有前景的方向，每个方向整合多个想法种子。

---

### 第三阶段：批判性评估（建设性筛选）

**目标**：评估有前景的想法，保持创造性动力。

#### 评估框架

对于每个有前景的方向：

1. **新颖性**
   - 这个想法与现有方法有何不同？
   - 是否解决了已知问题的新角度？

2. **可行性**
   - 技术上是否可行？
   - 需要什么资源？
   - 有哪些主要障碍？

3. **影响力**
   - 如果成功，能带来多大改进？
   - 是否解决了真正的痛点？

4. **风险**
   - 可能的失败点是什么？
   - 有哪些未知因素？

**输出**：选择 1 个最有前景的方向进行深入开发。

---

### 第四阶段：方案综合（具体化）

**目标**：将选定的方向转化为具体的解决方案。

#### 综合步骤

1. **问题定义**
   - 核心技术挑战
   - 关键约束和假设
   - 性能要求

2. **方法论设计**
   - 具体技术路径
   - 关键创新点
   - 理论基础

3. **实现考虑**
   - 所需资源
   - 潜在挑战
   - 验证方法

4. **文献定位**
   - 与现有工作的关系
   - 解决的研究空白
   - 新颖贡献

**输出**：完整的解决方案提案。

## 高级头脑风暴技术

当基础技术不够时，Proposer 使用这些高级方法：

### SCAMPER 框架

| 缩写 | 技术 | 应用 |
|------|------|------|
| S | Substitute（替代） | 可以用什么替代现有组件？ |
| C | Combine（组合） | 可以组合哪些方法？ |
| A | Adapt（适应） | 其他领域的方法如何适应？ |
| M | Modify（修改） | 可以修改什么参数？ |
| P | Put to other use（用于其他用途） | 还有其他应用场景吗？ |
| E | Eliminate（消除） | 可以移除什么约束？ |
| R | Reverse（反转） | 反转什么会怎样？ |

### 六顶思考帽

从多个视角分析问题：
- **白帽**：事实和数据
- **红帽**：直觉和感受
- **黑帽**：谨慎和风险
- **黄帽**：乐观和利益
- **绿帽**：创造性和替代方案
- **蓝帽**：过程控制

### 形态分析

系统性地探索参数空间：
1. 识别关键参数
2. 列出每个参数的可能值
3. 组合不同值生成新方案

### TRIZ 原则

解决技术矛盾：
- 分割原理
- 抽取原理
- 局部质量
- 非对称
- 合并
- 通用性
- 嵌套
- 反向补偿
- ...（共40条）

## 头脑风暴输出格式

Proposer 的最终输出应包含头脑风暴的痕迹：

```json
{
  "problem_analysis": {...},
  "proposed_solution": {...},
  "brainstorming_trace": {
    "ideas_generated": ["idea1", "idea2", ...],
    "patterns_identified": ["pattern1", "pattern2"],
    "promising_directions": [
      {
        "direction": "...",
        "novelty": "...",
        "feasibility": "..."
      }
    ],
    "selected_direction": "...",
    "rationale": "为什么选择这个方向"
  },
  "implementation": {...},
  "literature_positioning": {...}
}
```

---

## 注意事项

1. **数量 > 质量（初期）**：先大量生成想法，再筛选
2. **延迟评判**：发散阶段不批判，只生成
3. **鼓励激进**：考虑"最疯狂"的想法
4. **跨领域思维**：从其他无线/非无线领域寻找灵感
5. **系统性探索**：使用结构化方法覆盖想法空间

---


Proposer 模拟对话式头脑风暴的思维过程，但在内部完成所有步骤，最终输出一个深思熟虑的解决方案。
