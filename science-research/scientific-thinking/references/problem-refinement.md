# 科学问题凝练

## 定位：最重要的模式

科学问题是项目申请书的核心基础，也是整个研究的立足点。方向可以调整，方法可以更换，唯独科学问题立不住，后续一切工作都失去意义。

凝练科学问题**是重中之重，也是最具挑战性的环节**：它不是从文献里挑一个现成的，也不是把兴趣改个说法，而是把模糊的兴趣、观察和直觉，经过反复讨论与锻造，收敛成一个精确、可证伪、有新知识增量的问题。

**铁律：必须和用户反复讨论、一起思考。**
- 问题属于研究人员，不属于助手。助手提供的是结构、镜像、压力测试和领域知识，不是答案
- **不可以简单复制、罗列已有文献中的问题**——文献用来定位空白与基础，问题必须从用户自己的观察和判断中长出来
- 禁止一次性生成问题清单让用户挑选；每轮给 2-3 个候选和待决的分叉点，等用户回应后再继续
- 预期 3-5 轮以上的迭代；第一轮的表述几乎从来不是最终表述

## 与另外两种模式的关系

三种模式构成"生成—凝练—评估"链条：

| 模式 | 动作 | 输入 → 输出 |
|------|------|------------|
| 头脑风暴 | 发散 | 兴趣/现象/灵感 → 候选方向（多而杂） |
| **科学问题凝练** | 收敛 | 候选方向/模糊兴趣 → 精确科学问题（少而准） |
| 批判性思维 | 压测 | 科学问题/论文/证据 → 质量裁决 |

衔接：头脑风暴产出方向 → 本模式凝练成问题 → 批判性思维对问题做压力测试 → `scientific-writing` 技能写入申请书。

## 核心原则

### 1. 共创，不代劳

- 研究人员参与每一个关键判断；助手负责提出逼问、暴露分叉、供给领域知识和类比
- 回合制：每轮呈现"当前最佳表述 + 本轮变化 + 待用户裁决的问题"，然后停下等待
- 用户回应简短时，主动解读其倾向并复述确认（"你的意思是更倾向 A 的机理路径，但担心可行性——对吗？"），而不是继续单向输出
- 用户犹豫时，给判别依据和后果对比，不替用户拍板

### 2. 两性标准：每个候选问题都必须通过

科学问题的提出需突出"两性"：**创新性与科学性**。

**创新性**——解答该科学问题应推动新知识的产生，提升学科和研究领域的发展：
- 深入分析新特性及其影响，内容要具体、清晰
- 在标题和关键词等重要位置体现创新点——这是评审专家关注的重点

**科学性**——问题答案应可被证明或证伪，避免模糊和夸大其词：
- 采用自然科学公认的研究方法，鼓励创新和尝试
- 允许失败，重在过程，不怕做不到

### 3. 从文献定位，不从文献复制

- 文献的正确用途：确认空白、避免重复研究、找到"站在谁的肩膀上"的基础工作
- 文献的典型误用：把综述"未来方向"章节或他人列出的 open problem 原样搬来当自己的科学问题。别人清单上的问题是别人视角的产物，必须经过用户自己的观察、质疑和重铸，才能成为"你的"问题
- 面对文献中的 open problem，正确动作是逼问用户："这个 open problem 为什么一直没被解决？卡点在假设、工具还是问题本身提错了？你有什么不一样的切入点？"

### 4. 具体、清晰、可证伪

- 一句话说清问题；说不清就是还没凝练到位
- 问题中必须出现可操作、可测量的对象（变量、条件、机理），而非空转动词（"研究""探索""分析"）
- 拒绝夸大（"首次""全面""颠覆性"没有实体支撑时一律删掉）

## 凝练工作流（迭代式，非一次性）

### 第一阶段：素材盘点

**目标：** 摸清起点——用户手里到底有什么。

**问：**
- 最近观察到什么让你困惑或意外的现象？（实验反常、仿真异常、文献互相矛盾）
- 手头有什么独特资源？（数据、信道测量、硬件平台、代码库、合作关系）
- 这个方向上大家"理所当然"接受、但你隐约觉得可疑的假设是什么？
- 约束条件：时间、经费、团队能力边界

**输出：** 素材清单（观察 / 现象 / 矛盾 / 资源 / 约束）。若来自头脑风暴会话，以其第五阶段"最有前景的方向"为起点。

### 第二阶段：问题萌芽

**目标：** 从素材中长出候选问题（每轮 2-3 个，等用户反应）。

**锻造手法：**

| 手法 | 问法 | 通信语境示例 |
|------|------|-------------|
| 现象→机理 | "X 在什么条件下发生？由什么决定？" | "RIS 增益在近场为何偏离 N² 缩放律？" |
| 矛盾→冲突 | "A 文献说 X，B 文献说 Y，差异来自哪个未建模因素？" | "两组信道测量结论相反，是场景差还是方法差？" |
| 需求→瓶颈 | "要达到 X，卡住的环节是科学问题还是工程实现？" | "太赫兹组网卡在器件，还是卡在波束管理的机理？" |
| 假设挑战 | "如果领域公认假设不成立，什么会崩塌？" | "完美 CSI 假设去掉后，哪些结论还站得住？" |
| 边界推移 | "该规律在更极端条件下还成立吗？" | "超大规模阵列下自由度理论是否失效？" |

**关键区分：科学问题 vs 工程目标 vs 方法描述**
- "把 RIS 链路增益提升 3 dB"——工程目标（性能指标，不揭示未知）
- "用深度学习做波束预测"——方法描述（没说清未知是什么）
- "无源约束与离散相位下，RIS 可达波束赋形自由度的极限由什么物理机制决定"——科学问题（答案揭示未知机理/规律/关系）

**判别法：** 回答这个问题之后，世界多出的是"对某种机理/规律/关系的认识"，还是仅仅"一套更好的系统参数"？后者不算科学问题。

### 第三阶段：两性检验

**目标：** 每个候选问题过两性检查表，给出裁决：**成立 / 收窄后成立 / 砍掉**。

**创新性检验：**
- **新知识测试：** 回答了它，学科多了什么新认识？若答案是"更好的系统"，创新性不足
- **SOTA 距离：** 检索确认是否已被解决；已解决 → 砍掉（见下方深度评估流程）
- **新特性分析：** 所依据的新特性（新频段/新硬件/新架构/新范式）及其影响是否具体、清晰？
- **表述测试：** 创新点能否前置到标题和关键词？

**科学性检验：**
- **可证伪测试：** 什么样的观测或实验结果能证明它错了？答不出证伪路径的问题不合格
- **方法测试：** 是否存在自然科学公认的研究路径（理论推导 + 仿真验证 + 实验/原型）？
- **去模糊测试：** 划掉空转动词后还剩什么可操作对象？有没有夸大词？
- **过程价值：** 即使结果是否定的（假设被证伪、机制不存在），认识上是否仍有增量？（允许失败，重在过程）

**深度评估流程（每个进入"成立"名单的候选必做）：**
- 深挖文献库（语义检索 + 标题检索 + 关键文献摘要）
- 网络检索知识库外的重要文献（特别是最新综述和竞争工作）
- 对问题给出裁决：成立 / 收窄后成立 / 已被解决应砍掉
- 明确"站在谁的肩膀上"——引用关键基础工作
- 发现重要文献但缺少原文时，列出题目和出处请用户下载

### 第四阶段：收窄与精确化（核心迭代环节）

**目标：** 把"成立"的问题打磨到一句话精确表述。这是与用户来回轮次最多的阶段。

**问题句式：**
> 在 **[场景/条件]** 下，**[变量/机制]** 如何/为何 影响 **[可测量结果]**？

**收窄手段：**
- 限定条件：频段、场景、假设边界（"在近场太赫兹场景下"）
- 拆解子问题：主问题之下分解 2-4 个可独立验证的子问题
- 变量化：把模糊名词变成可测对象（"信道特性" → "多径角度扩展随阵列孔径的演化规律"）

**常见病诊断：**

| 病症 | 表现 | 处方 |
|------|------|------|
| 大而空 | "研究 6G 信道" | 限定条件 + 变量化 |
| 目标当问题 | "实现 Tbps 吞吐" | 逼问其背后的未知机理 |
| 方法当问题 | "用深度学习做 X" | 改问"它为什么有效/学到的是什么映射/何时失效" |
| 文献搬运 | 原样照搬综述 open problem | 用用户自己的观察与切入点重铸 |
| 夸大模糊 | "全面研究""首次提出"无实体 | 删虚词，落到可测量对象 |

**每轮输出格式：**
1. 当前最佳问题表述（一句话）
2. 本轮相对上一轮的变化及理由
3. 待用户裁决的分叉点（"A 路径机理深但风险高，B 路径稳但增量小——你倾向哪个？"）

然后停止，等用户回应。不自问自答，不连续推进多轮。

### 第五阶段：定稿交付

**目标：** 产出可直接进入申请书/开题的"科学问题凝练卡"。

```markdown
## 科学问题凝练卡（YYYY-MM-DD）

### 主问题
[一句话主问题，条件-变量-结果三要素齐全]

### 子问题分解
1. [子问题 1]（对应验证手段：理论/仿真/实验）
2. [子问题 2]……

### 两性论证
- 创新性：[新知识增量是什么；与 SOTA 的精确距离；新特性及其影响]
- 科学性：[证伪路径；拟采用的公认方法；过程价值（否定结果也有认识增量）]

### 站在谁的肩膀上
[关键基础工作清单，注明各工作解决了什么、遗留什么]

### 标题与关键词建议
[创新点前置的表述方案，1-2 个候选]

### 风险与备选
[最大技术风险；若主路径受挫的备选问题]
```

**结束方式：**
- 建议把凝练卡交给批判性思维模式做最后一轮压力测试："如果我是评审专家，看到这个问题会问什么？"
- 确认后可进入 `scientific-writing` 的申请书/论文工作流

## 常见反模式（禁止）

| 反模式 | 表现 | 为什么禁止 |
|--------|------|-----------|
| 问题清单倾倒 | 一次生成 5-10 个问题让用户挑 | 用户失去思考过程；问题是用户的，不是助手的 |
| 文献罗列 | 把综述"未来方向"抄成问题 | 复制的问题没有用户的观察与视角，创新性存疑 |
| 自问自答 | 不等用户回应连推多轮 | 迭代凝练的本质是反复讨论，跳过讨论就退化成代写 |
| 夸大模糊 | "首次""全面""颠覆性"堆砌 | 恰是评审反感的信号；两性双输 |
| 越俎代庖 | 替用户在方向分叉上拍板 | 问题的主人始终是研究人员 |
| 一步到位 | 第一轮就想定稿 | 凝练必然多轮；抢进度必然产出空泛问题 |
