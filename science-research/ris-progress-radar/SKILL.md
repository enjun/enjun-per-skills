> **本技能仅限用户手动调用**（`disable-model-invocation: true` 已使其对模型不可见）：单次运行派出 3 个联网调研子代理，token 消耗大（百万级）、耗时 20-40 分钟。

# RIS 研究进展雷达

一次运行 = **并行派出 3 个信息收集子代理**（学术 / 标准化 / 工业界）→ 主代理**去重综合** → 生成结构化中文报告。全程预计 20-40 分钟。

## 0. 为什么这样设计

- RIS 领域的进展散落在三类完全不同的渠道：学术论文（快但嘈杂）、标准组织文档（慢但权威）、厂商新闻（快但良莠不齐）。单一渠道的调研必然有盲区，所以分三路并行收集。
- "最近 3 个月"是动态窗口，**子代理不知道今天的日期**。所有子代理提示词必须写入明确算好的起止日期（ISO 格式），否则会检索到过期内容还浑然不觉。
- 工业界新闻常有夸大宣传，学术论文也有低水平重复。报告必须区分"确证进展"和"宣传性消息"，所以每条信息要标注可信度等级。

## 1. 运行流程总览

```
① 解析参数（时间窗口 / 子主题 / 详略侧重 / 输出路径）
② 读 references/ 下的支持文件（关键词、信息源、简报模板、报告模板、状态基线）
③ 同一条消息里并行派出 3 个子代理（academic / standards / industry）
④ 等待返回，记录各代理的覆盖情况（查了哪些源、哪些源失败/跳过）
⑤ 去重、按可信度分级、跨来源交叉印证
⑥ 按 references/report-template.md 撰写报告，保存为 Markdown 文件
⑦ 在对话中给出 TL;DR 摘要 + 文件路径
⑧ 把本次确认的领域新状态写回 references/state-baseline.md（下次运行因此更快）
```

## 2. 步骤详解

### ① 解析参数

调用形式：`/ris-progress-radar [子主题或侧重] [时间范围]`。用户本次输入的参数为：

> $ARGUMENTS

（为空即无参数。）按语义解析（如"近场RIS"是子主题，"重点：标准化与产品化"是侧重，"最近半年"是时间范围）；无参数时全部取默认值。

| 参数 | 默认值 | 说明 |
|---|---|---|
| 时间窗口 | 今天往前推 3 个月 | 先算出明确的 `START_DATE` 和 `END_DATE`（今天），写成 ISO 格式。用户说"最近半年""今年 Q2"时换算成对应区间 |
| 主题范围 | RIS 全景 | 用户指定子主题时（如"近场RIS""RIS通感一体化""RIS硬件实现"），三个代理都聚焦该子主题，但标准化/工业界部分仍保留全景中与子主题直接相关的条目 |
| 详略侧重 | 三路均衡 | 用户指定侧重时（如"重点：标准化与产品化"），被侧重路线完整深挖，其余路线精简为概况+代表作，报告篇幅比例随之调整 |
| 输出路径 | `./RIS进展调研_<窗口起>_<窗口止>.md` | 用户指定路径/文件名时从之 |

把这几个参数写清楚后才开始派代理——后面所有提示词都引用它们。

### ② 准备收集简报

按需读取（不读全文上下文装不下时，至少读齐三个简报模板）：

- `references/keywords.md` — RIS 关键词矩阵。**每次都要用**：RIS 的同义词/变体极多（RIS/IRS/智能超表面/STAR-RIS/BD-RIS/SIM...），只搜 "RIS" 会漏掉近一半文献；工业界还常混用 smart repeater。
- `references/state-baseline.md` — 领域状态基线（上次运行的快照）。**每次都要读**：里面有 3GPP 证据链结论与下次观察点、玩家名单、总量参考值、已核查的阴性结果。运行时的正确姿势是"验证增量"：直接核查基线指出的观察点（如下次 3GPP 会议议程），复核关键结论是否仍成立，而不是从零重建证据链——这能省掉大量重复检索。
- `references/collection-briefs.md` — 三个子代理的完整提示词模板（已内置各自的信息源清单、检索策略、输出格式）。组装时：填入日期窗口和子主题，按子主题裁剪关键词。
- `references/report-template.md` — 报告六章结构模板。撰写阶段再读。
- `references/sources.md` — 各信息源的访问方式与踩坑记录。仅在需要排查某源访问问题时查阅。

### ③ 并行派出子代理

**在同一条消息里发出全部 3 个 Agent 调用**（不要串行等待，也不要先派两个再补第三个）：

| 代理 | 覆盖 | 依托 |
|---|---|---|
| academic | IEEE Xplore 顶刊新论文、arXiv 预印本、窗口内顶会论文集、新综述 | `~/.claude/skills/ieee-literature-search/`（IEEE 检索方法）+ WebSearch |
| standards | 3GPP Rel-19/Rel-20 相关讨论与立项、ETSI/ITU/CCSA/IMT-2030 推进组动态 | `~/.claude/skills/3gpp-access/`（3GPP FTP 访问）+ WebSearch |
| industry | 设备商/运营商/芯片商动态、创业公司与投融资、现场试验与商用试点、窗口内展会 | WebSearch/WebFetch（信息源清单见简报） |

子代理是通用代理，**不会自动加载其他技能**——提示词中必须写明"先阅读 ~/.claude/skills/ieee-literature-search/SKILL.md 再按其方法执行检索"。

每个代理返回统一格式的条目清单（格式见简报模板），主代理不做二次检索补充——覆盖不足宁可记入报告的"盲区"，也不悄悄补漏导致报告覆盖度失真。

### ④-⑤ 收集、去重、分级

- **去重**：同一事件常被学术、工业两路同时命中（如某厂商试验发了会议论文）。合并为一条，标注多来源。
- **可信度分级**（每条必标）：
  - `[A]` 官方一手来源：标准组织文档、厂商官方新闻稿、论文原文、监管机构公告
  - `[B]` 权威行业媒体转述（C114、Light Reading、6GWorld 等）
  - `[C]` 自媒体/论坛/无原始出处的消息
  - "重要进展总结"章节只允许引用 A/B 类；C 类单独归入"待证实消息"并在报告中明示。
- **交叉印证**：一项重要进展若有 ≥2 个独立来源，可信度加注"多源印证"。只有单一宣传来源、且带明显营销话术的，降级处理。

### ⑥ 撰写报告

读 `references/report-template.md`，按其六章结构撰写。写作要求：

1. **每条进展必须带**：日期（窗口内）、来源链接、可信度标记、一两句"为什么重要"的点评。没有日期的条目不入选——进展报告的核心价值就是时间敏感性。
2. **语言**：中文正文，专业名词保留英文原文（如 STAR-RIS、NCR、 beam squint），中文译名首次出现时括注。
3. **诚实呈现盲区**：附录"信息源覆盖情况"如实记录哪些源查了、哪些失败/跳过/被反爬，让读者知道覆盖度边界。查不到 ≠ 不存在。
4. **"存在问题"章节是重头**：从三路信息中提炼领域公认的未解难题（如硬件损耗、信道估计开销、标准化缺位、商业模式不清），区分"学术界承认的挑战"（有文献支撑）和"产业界反馈的现实障碍"（有新闻/报告支撑），各给出处。
5. **研究启示**（可选但默认包含）：结合团队研究方向（RIS、ISAC、近场通信）给出 2-3 条可操作启示，明确标注为主观判断。

### ⑦ 对话摘要

报告落盘后，在对话中给出：3-5 条最重要进展 + 2-3 个核心问题 + 文件路径 + 各代理覆盖情况一句话。不要把整份报告贴进对话。

### ⑧ 更新状态基线

把本次运行**确认的新状态**写回 `references/state-baseline.md`（即本次读取的那份），替换头部"截至"日期：

- 标准化：新的 3GPP 会议核查结论（替换旧的观察点，写入下一次会议时间表）、其他组织新交付物
- 学术：新窗口的总量参考值、热点格局变化
- 工业：玩家状态表更新、新的商业化锚点、新的阴性结果与政策动态
- 超过 6 个月未复核的条目标注失效

这一步让技能随使用越来越快：下次运行只需验证增量，不必重建 3GPP 证据链、重新发现玩家名单。写入要克制——只写"经验证的状态"，不写单篇论文级细节（那些留在报告里）。

## 3. 失败降级

- **某个子代理失败/超时**：用其余两路结果出报告，附录中明确标注该路缺失；不要静默跳过。
- **IEEE 机构登录不可用**：学术代理降级为 arXiv + WebSearch（IEEE 摘要页通常免登录可读），并在覆盖情况中说明。
- **3GPP FTP 被反爬**：按 3gpp-access 技能中的降级路径走 portal.3gpp.org；再失败则用 WebSearch 搜第三方转述（如 3GPP 官网新闻、6GWorld 会议报道），降为 B 类。
- **窗口内某信息源确实无更新**：如 3GPP 会议间隙，如实写"本窗口内无 X 动态"——这也是有效信息。

## 4. 常见陷阱（实战教训）

- **子代理凭记忆写"最近进展"**：模型训练截止日之后的进展只能来自实际检索。提示词中明确"禁止凭内部知识罗列进展，每条必须有本次检索到的 URL 佐证"。
- **日期窗口算错**：用"2026-07-07 至 2026-10-07"这种显式区间，禁止"最近三个月"这种相对表述出现在子代理提示词里。
- **把相邻领域算进来**：fluid antenna (FAS)、holographic MIMO、dynamic metasurface antenna 与 RIS 高度相关但边界模糊。全景模式下 FAS/HMIMO 相关成果可收录但单独归组；子主题模式下严格按用户指定范围。
- **3GPP 的 RIS 用词陷阱**：3GPP 正式立项的是 Network-Controlled Repeater（NCR，Rel-18 已标准化的放大转发设备）而非 RIS 本体；RIS 相关讨论散落在 6G 研究与 workshop 文稿中，用词还可能是 reconfigurable surface / smart surface。检索时关键词要放宽，归类时要把 NCR 和 RIS 区分开。
