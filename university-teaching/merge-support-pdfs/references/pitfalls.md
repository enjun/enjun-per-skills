# 已验证的坑与解法（症状 → 原因 → 解法）

以下问题全部在实际项目中出现过，解法均已实践验证。按类别整理；装配脚本 `assemble.py` 与 `add_item_titles.py` 已内置大部分解法，遇新问题时按下表排查。

## 一、pypdf 装配类

### 1. 叠加的页码/水印“消失”，页面内容正常
- **症状**：assemble 报告“页码覆盖页数: N”正常，但渲染成品页面上看不到页码。
- **原因**：`writer.add_page(reader.pages[i])` 加入的是**副本**；随后对 `reader.pages[i]`（读取器的页对象）做 `merge_page`/`merge_transformed_page`，修改不会进入成品。
- **解法**：先加完全部页，再遍历 **`writer.pages`** 逐页叠加页码戳（assemble.py 的“对 writer 的页对象叠加”段）。

### 2. Acrobat 打开正常，编辑保存时报“数字越界”无法保存
- **症状**：合并产物可读可打印，Acrobat 编辑后保存失败。
- **原因**：多次 pypdf 合并/裁剪后残留**悬空对象引用**（对象流引用不存在的对象号），Acrobat 校验严格拒绝保存；普通阅读器会容错忽略。
- **解法**：用 PyMuPDF 重存：`new.save(tmp, garbage=4, deflate=True, clean=True)`；逐项扫描验证 `xref_object(x)` 内引用的对象号全部 `< xref_length`。若个别源文件仍带入坏引用（如内嵌字体 `/Length2 18 0 R` 悬空），把该文件的页面**重建为纯图像页**（单图页用 `extract_image` 无损提取原图插入；多图/混排页用 200dpi 渲染图插入），再重装整册。
- **注意区分**：pypdf 的 "wrong pointing object" 常是良性警告；MuPDF 的 "cannot find object in xref" 才是硬伤。

### 3. 页码在部分页面被裁掉/看不到
- **症状**：多数页面页码正常，个别页面（尤其非A4尺寸页）页码缺失。
- **原因**：叠加偏移用 `max(0, 目标宽-叠加宽)` 截断——当目标页比叠加页**矮**（如横版 842x595 对 A4竖版戳 595x842）时，负偏移被截为0，页码落在目标页之外被裁掉。
- **解法**：偏移不截断，直接 `tx = 目标宽 - 595.32, ty = 目标高 - 841.92`（负数合法，页码随负偏移落在目标页内右下角）。assemble.py 已内置。

### 4. 混合页面尺寸导致页码位置不一致
- **现象**：材料PDF有 A4(595x842)、Letter(612x792)、横版(842x595)、扫描长条(964x679)等多种尺寸。
- **解法**：页码戳用固定 A4 竖版页；叠加时按目标页尺寸计算偏移（同上）。尺寸清单用 PyMuPDF 统计：`Counter((round(p.rect.width), round(p.rect.height)) for p in doc)`。转 Word 文档时显式设 A4（默认可能是 Letter）。

### 5. 带 /Rotate 的页：叠加内容旋转错位/丢失
- **症状**：`/Rotate=90/270` 的页，叠加的页码或标题条竖排、跑到页外。
- **原因**：叠加内容按未旋转坐标写入，渲染时又被页面 /Rotate 二次旋转。
- **解法**：装配时检测 `p.rotation`，非0页先“烘焙”：`get_pixmap(dpi=200)` 渲染 → 新建同尺寸图像页插入。烘焙后页码正常。整册不应残留旋转页（assemble 自检会报告）。

## 二、源文件类

### 6. 扫描件/证书 PDF 无文本层
- **现象**：`get_text()` 返回空，无法按文本定位或检测“是否已有标题”。
- **解法**：检测用 pdftoppm 渲染 + PIL 找顶部第一行非白像素（top_blank_px）判断留白；标题用 PIL 画在渲染图上再整页替换。图像化后丢失文本层，佐证材料可接受。

### 7. 源 PDF 内嵌字体对象悬空（如 `/Length2 18 0 R` 无对应对象）
- **症状**：整册重存时 MuPDF 报 "cannot find object in xref (18 0 R)"。
- **解法**：定位到具体文件（逐文件 insert_pdf 到空文档，看 MuPDF warnings）；把该文件每页重建为嵌入图像页（单图页 `extract_image` 无损提取原图；多图/混排页 200dpi 渲染插入）。

### 8. 页面 MediaBox 高度为负（如 595x-842）
- **原因**：源工具写出了倒序 MediaBox（y1>y2）。
- **处理**：尺寸取绝对值；直接叠加会方向错乱——安全做法是整页替换（渲染→画标题→替换，即 add_item_titles.py 的路径）。

### 9. 前缀匹配陷阱
- **规则**：按序号找文件用 `re.match(rf"^{n}([\s\-（]|$)", f)`——裸 `f.startswith(str(n))` 会把 “10-…” 误配给序号1。
- **源文件旧序号**：学院原始文件夹中的文件可能保留**重编号前**的旧序号（如合并版序号49 的原件在网安目录里叫 “52 2025年中国专利优秀奖证书….pdf”、序号50 叫 “53 …”）。恢复源文件时用显式路径映射表（fix_titles3.py 的 SRC 字典），不要按序号猜。

### 10. 名称尾缀人工标注
- 记录表名称可能带 `（戴校？）（许校？）（刘晓勇？）` 等待确认标注，写进标题/目录前去除：`re.sub(r"（(戴校|许校|刘晓勇)？?）$", "", name)`。

## 三、Word COM 类

### 11. 页脚页码对齐被重置（页码跑到左侧）
- **原因**：`Fields.Add(fp, 33)`（插入 PAGE 域）会重置段落对齐。
- **解法**：**先**加域，**后**设 `fp.ParagraphFormat.Alignment = 2`。页脚访问路径是 `d.Sections(1).Footers(1).Range`（Document 对象没有 Footers 属性）。

### 12. 封面溢出为两页
- **原因**：Word 段前距会被 `TypeParagraph` 后的新段落继承——首段 SpaceBefore=150 会延续到所有后续段。
- **解法**：第二段起把 SpaceBefore 清零（如30）；或每行内容用独立文档。装配前断言封面页数==1。

### 13. 分类标题页不垂直居中/不在页面中部
- **原因**：同一文档内 `InsertBreak`（分页符）后的段落，段前距不生效。
- **解法**：每个分类标题用**独立文档**生成（设置 `Sections(1).PageSetup.VerticalAlignment = 1` 垂直居中），导出后按页拆分合并为 _dividers.pdf。

### 14. 新建文档默认页面尺寸是 Letter（612x792）
- **解法**：new_doc 里显式设 `PageWidth=595.3, PageHeight=841.9`（A4）及四边距（上下72、左右90pt，可用宽415pt——目录右对齐制表位就定在415）。

### 15. docx→PDF 与页数统计
- **转换**：`d.ExportAsFixedFormat(out, 17)`（17=PDF）；`ReadOnly=True` 打开可避免部分占用问题；文件被用户在 Word 中打开时写入会失败（PermissionError/EBUSY）——先关闭或改写到临时名。
- **页数**：`ComputeStatistics` 不可信，用 pypdf `len(PdfReader(pdf).pages)`。

### 16. 增量转换的缓存陷阱
- **症状**：更新了 docx，重跑转换仍输出旧内容。
- **原因**：转换脚本“跳过已存在PDF”的增量逻辑。
- **解法**：更新/删除 docx 后，先删除 `_pdf/` 里对应的旧 PDF（或整体清空重转），再跑转换。

### 17. 目标文件被占用
- Word/Excel/Acrobat 打开目标文件时，写入报 EBUSY/PermissionError。
- 解法：写到 `.tmp` 后 `os.replace`（对 Word 打开的 doc 无效）；xlsx 被打开时用 `GetActiveObject('Excel.Application')` 找到已打开工作簿经 COM 直接改并 Save；docx 被打开时只能请用户关闭。

## 四、排版与目录类

### 18. TOC 两遍法
- 第一遍用占位符（无页码）导出，确定目录总页数 T；按 T 计算真实页码；第二遍回填。两遍条目文本除页码数字外完全相同（换行数不变）→ 页数稳定，导出后断言 `t2 == t1`。
- **条目页码累加是 `cur += pp`（该项实际页数），不是 +1**——此错误曾导致整册目录页码全部错误（症状：目录页码远小于实际页码）。

### 19. 首页标题规范（与正文同页，不另起页）
- 用户要求：标题与材料正文同页。PDF 用“渲染首页→顶部留白检测→直接写入/缩放让位→整页替换”（add_item_titles.py）；docx 在正文开头插入标题段（左对齐黑体加粗14pt）。
- **不要用**前置独立标题页 + 原地叠加白色标题条的组合：PIL 生成的横条页合并后方向不可控（第 24 条），且白条会覆盖扫描件顶部内容。
- 标题留白足够时直接写入留白区（不缩放）；不足时才缩放让位。

### 20. 分类标题页
- 每分类一个独立 Word 文档：`Sections(1).PageSetup.VerticalAlignment = 1`（垂直居中）+ 水平居中，黑体40pt加粗；导出后合并为 _dividers.pdf；标题页占1页计入页码，目录中分类行指向标题页。

### 21. 内容超长页的整页替换
- 首页内容超高/超宽（如长截图）时，渲染图等比缩放进标题条以下的区域即可（LANCZOS），不损失内容。

### 22. 旋转页烘焙
- 烘焙时页尺寸取渲染图的物理尺寸：`w, h = pix.width*72/200, pix.height*72/200`——旋转后的渲染图已按可视方向输出，烘焙后页码叠加位置正确。

## 五、流程类

### 23. 重复合并的自检三件套（assemble.py 已内置）
1. 悬空引用扫描（0 为合格）；
2. 逐页右下角页码文本检查（除封面全覆盖，`str(i) in 右下角clip文本`）；
3. 旋转页清单（应为空）。
再加 pdftoppm 抽样目检：封面、目录、分类标题页、横版页、若干正文页拼网格图一次看完。

### 24. 材料文件夹来源映射
- 学院原始文件夹中的原件可用于恢复“合并版”里被误处理的文件；恢复前先 `PdfReader` 确认页数一致。注意旧序号（第 9 条）和同名多副本（合并版与学院文件夹各一份时，学院那份才是干净原件）。

### 25. 文件占用
- Word/Excel/Acrobat 打开目标文件时，写入会 EBUSY/PermissionError。先让用户关闭，或写到 `.tmp` 后 `os.replace`（对 Excel 打开的 xlsx 无效——需改用 Excel COM `GetActiveObject` 编辑已打开工作簿并 Save）。

### 26. xlsx 被占用时的写入
- `openpyxl.load_workbook + save` 在 Excel 打开时抛 PermissionError；改用 `win32com.client.GetActiveObject('Excel.Application')` 找到已打开工作簿直接改单元格并 `wb.Save()`。

### 27. 输出文件名页号位数不定
- pdftoppm 输出名可能是 `file-1.png` 或 `file-001.png`（按总页数位数），按前缀 glob 查找，不要拼死文件名。
